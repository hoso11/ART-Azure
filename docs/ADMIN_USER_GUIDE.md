# ART Manufacturing — Ադմինիստրատորի ուղեցույց

Ուղեցույց ադմին-իրավասությամբ օգտատերերի համար։ Բացատրում է, թե ինչպես կառավարել ապրանքները, պատվերները, պահեստը, արտադրությունը, հաճախորդներին, օգտատերերին և հաշվետվությունները, և ինչպես անվտանգ ջնջել սխալ կամ ավելորդ տվյալները։

> Ուղեցույցում English-ով են գրված միայն այն բառերը, որոնք համակարգում ուղղակիորեն երևում են այդ տեսքով՝ `FORCE DELETE`, `SKU`, `ID`, `Email`։ Մնացած ամեն ինչ հայերեն է։

## 1. Ներածություն

### Համակարգի նպատակը

ART Manufacturing համակարգը ստեղծված է հագուստի արտադրությամբ զբաղվող ընկերության գործառնական կառավարման համար։ Համակարգում միասին են՝

- Հաճախորդների բազան և նրանց պատվերները։
- Ապրանքների կատալոգը՝ բոլոր տարբերակներով, գույներով, չափսերով։
- Պահեստի նյութերը և դրանց շարժը։
- Արտադրության գործընթացը՝ սկսած կտրումից մինչև առաքման պատրաստ վիճակ։
- Հաշվետվությունները՝ վաճառքների, պաշարների, արտադրության։
- Բոլոր գործողությունների պատմությունը (աուդիտ)։

### Ադմին-իրավասությամբ ինչ կարելի է կառավարել

Ադմինը կարող է՝

- Ստեղծել, խմբագրել և ջնջել ապրանքները, տարբերակները, կատեգորիաները։
- Կառավարել պահեստի նյութերը և բաղադրատոմսերը։
- Ստեղծել և կառավարել պատվերները։
- Սկսել և կառավարել արտադրությունները։
- Կառավարել հաճախորդները։
- Ստեղծել նոր օգտատերեր և տալ դերեր։
- Ստեղծել հաշվետվություններ։
- Տեսնել գործողությունների ողջ պատմությունը։

### Ջնջելու երեք եղանակ — տարբերությունը

Համակարգում կա ջնջելու երեք տարբեր եղանակ։ Կարևոր է հասկանալ տարբերությունը՝

**1. Արխիվացում (փափուկ ջնջում)**
Տվյալը մնում է բազայում, բայց հայտնվում է որպես «Անակտիվ»։ Հին պատվերներն ու հաշվետվությունները չեն խախտվում։ Կարելի է հետագայում նորից ակտիվացնել։ Օգտագործվում է հաճախորդների և օգտատերերի համար։

**2. Ջնջել (նորմալ ջնջում)**
Տվյալը ընդմիշտ հեռանում է բազայից։ Համակարգը նախ ստուգում է, արդյոք տվյալը կապված է այլ տեղ։ Եթե այո — ջնջումը մերժվում է հստակ սխալի հաղորդագրությամբ։ Օրինակ՝ ապրանքը կապված է պատվերի հետ, կամ նյութն ունի պահեստի շարժեր։

**3. Ուժով ջնջել (Force Delete)**
Միայն ադմինի համար։ Ստիպում է ջնջել նույնիսկ այն դեպքում, երբ տվյալը կապված է այլ տեղ։ Կապված գրառումները չեն ջնջվում — դրանք պահպանվում են որպես «(ջնջված)» հղում։ Պահանջում է հաստատման մուտքագրել `FORCE DELETE` տեքստը։ Անդարձելի է։

## 2. Մուտք և նավիգացիա

### Մուտք

Մուտքի էջում մուտքագրեք ձեր `Email`-ը և գաղտնաբառը, սեղմեք **«Մուտք»**։

Եթե սխալ տվյալներ եք մուտքագրում մի քանի անգամ՝ համակարգը ժամանակավորապես կդադարեցնի փորձերը։ Սպասեք մեկ րոպե և կրկին փորձեք։

### Հիմնական բաժինները (ձախ կողմի մենյու)

Մուտքից հետո ձախում երևում է գլխավոր մենյուն։ Ադմինի համար հասանելի են բոլոր բաժինները՝

| Բաժին | Նշանակություն |
|---|---|
| **Վահանակ** | Գլխավոր էջ՝ ընդհանուր ցուցանիշներով։ Ակտիվ պատվերներ, ուշացած պատվերներ, ցածր մնացորդով նյութեր, արտադրության մեջ եղած պատվերներ։ |
| **Ապրանքներ** | Ապրանքների ցանկ՝ տարբերակներով։ Կարելի է ստեղծել, խմբագրել, ջնջել։ |
| **Պահեստ** | Նյութերի ցանկ, առկա քանակներով։ Ցածր մնացորդը նշվում է կարմիր։ |
| **Պատվերներ** | Հաճախորդների պատվերները։ Ֆիլտրեր ըստ կարգավիճակի, ուշացածների։ |
| **Արտադրություն** | Պատվերների արտադրության փուլերը և պահեստի համար արտադրությունները (Շարք)։ |
| **Հաճախորդներ** | Հաճախորդների բազան։ |
| **Օգտատերեր** | Համակարգի մուտք ունեցող մարդիկ՝ դերերով։ |
| **Հաշվետվություններ** | Վաճառքի, պաշարի, արտադրության հաշվետվություններ։ Կարելի է արտահանել CSV ձևաչափով։ |
| **Գործողությունների պատմություն** | Աուդիտի մատյանը՝ ով, երբ, ինչ արեց։ |

### Վահանակի վիճակագրությունը

Վահանակը ցույց է տալիս չորս հիմնական թիվ՝

- **Ակտիվ պատվերներ** — ընթացքի մեջ եղած պատվերների քանակը։
- **Ուշացած պատվերներ** — այն պատվերները, որոնց վերջնաժամկետն անցել է, իսկ կարգավիճակը դեռ չավարտված է։
- **Ցածր մնացորդ ունեցող ապրանքներ** — պահեստի այն նյութերը, որոնց առկա քանակը ցածր է սահմանված շեմից։
- **Արտադրության մեջ** — այն պատվերները, որոնք ակտիվ արտադրության մեջ են։

Յուրաքանչյուր թիվ սեղմելիս բացվում է համապատասխան էջը՝ արդեն կիրառված ֆիլտրով։

## 3. Ապրանքներ

### Ապրանքի ստեղծում

1. Անցեք **«Ապրանքներ»** բաժին։
2. Սեղմեք **«Ստեղծել ապրանք»** կոճակը։
3. Լրացրեք՝
   - **Անվանում** — հաճախորդին երևացող անունը։
   - **Արտիկուլ** (`SKU`) — եզակի կոդը։ Չի կարող կրկնվել։
   - **Կատեգորիա** — ընտրեք գոյություն ունեցողից, կամ նախ ստեղծեք նորը (տես [Կատեգորիաներ](#6-կատեգորիաներ))։
   - **Նկարագրություն** — ընտրովի։
4. Ստեղծելու պահին պարտադիր է ավելացնել առնվազն մեկ **տարբերակ** (չափս + գույն + գին + սկզբնական քանակ)։
5. Սեղմեք **«Պահպանել»**։

### Ապրանքի խմբագրում

Բացեք ապրանքի էջը՝ սեղմելով անվանումը կամ **«Տեսնել»**։ Աջ կողմում երևում է **«Խմբագրել»** կոճակը (միայն ադմինի համար)։ Կարող եք փոխել անունը, կատեգորիան, նկարագրությունը։ Արտիկուլը նույնպես փոխվում է, սակայն խորհուրդ չի տրվում փոխել արդեն օգտագործվածը։

### Տարբերակների ավելացում

Ապրանքի էջում **«Տարբերակատ-ներ»** բաժնում սեղմեք **«+ Ավելացնել տարբերակ»**։ Մուտքագրեք չափսը, գույնը, գինը, սկզբնական մնացորդը։

> Կարևոր է. եթե նոր տարբերակի համար ուզում եք, որ պահեստի մնացորդը մեծացնելու ժամանակ ավտոմատ նվազեցվեն հումքի պաշարները, անհրաժեշտ է ավելացնել **նյութական պահանջներ** այդ չափսի համար (տես ստորև)։

### Նկարների ավելացում

Ապրանքի էջի **«Նկարներ»** բաժնում սեղմեք վերբեռնման հատվածը, ընտրեք JPEG / PNG / WebP ֆայլ (առավելագույնը 5 MB)։ Մեկ ապրանք կարող է ունենալ մի քանի նկար։ Հիմնական նկարը (որը երևալու է կատալոգում) կարող եք նշանակել՝ սեղմելով համապատասխան նկարի կողքին։

### Բաղադրատոմս / նյութական պահանջներ

Ապրանքի էջում, ներքևում, կա **«Նյութական պահանջներ»** աղյուսակը։ Այստեղ սահմանվում է, թե յուրաքանչյուր չափսի մեկ պատրաստի արտադրանքի համար որքան նյութ է անհրաժեշտ։

Օրինակ՝ «M» չափսի մեկ շորի համար անհրաժեշտ է 1.5 մետր կտոր և 0.5 մետր ժապավեն։

Ավելացնելու համար ընտրեք նյութը, չափսը, քանակը մեկ հատի համար։ Սեղմեք **«+ Ավելացնել»**։

> Այս տեղեկությունը հիմք է հանդիսանում պաշարի ավտոմատ հաշվարկման համար։ Երբ տարբերակի մնացորդը մեծացնեք, համակարգը կնվազեցնի համապատասխան նյութերի քանակը պահեստից։

### Ապրանքի արխիվացում («Ջնջել»)

Ապրանքի էջում սեղմեք **«Ջնջել»**։ Ապրանքը կարխիվացվի՝ կարգավիճակը կդառնա «Անակտիվ»։ Տեսանելի չի լինի կատալոգում և նոր պատվերներում, բայց պատմական պատվերներն ու հաշվետվությունները կպահպանվեն։

### Ապրանքի ուժով ջնջում

Ուժով ջնջումը հնարավոր է **միայն եթե**՝

- Դուք ադմին եք։
- Ապրանքը արխիվացված է (անակտիվ վիճակում)։
- Ապրանքն ունի **զրո տարբերակ**։
- Ապրանքն ունի **զրո արտադրություն**։

Եթե ապրանքն ունի տարբերակներ, ապրանքների ցանկում կտեսնեք հուշում.
> «Ապրանքը արխիվացված է, բայց չի կարող ընդմիշտ ջնջվել մինչև մնում են տարբերակներ»

Հետևեք [«Անվտանգ աշխատանքի օրինակներ»](#14-անվտանգ-աշխատանքի-օրինակներ) բաժնի **B** օրինակին։

### Ինչպես մաքրել տարբերակները՝ ապրանքը ջնջելուց առաջ

1. Բացեք ապրանքի էջը։
2. Տարբերակների աղյուսակում սեղմեք յուրաքանչյուր տարբերակի կողքի **ջնջելու** կոճակը։
3. Եթե տարբերակը կապված է պատվերի կամ արտադրության հետ, կարմիր նշումով կհայտնվի **«Ուժով ջնջել»** կոճակը (տե՛ս [բաժին 4](#4-ապրանքի-տարբերակներ))։
4. Բոլոր տարբերակները ջնջելուց հետո վերադարձեք ապրանքների ցանկ՝ ուժով ջնջելու համար։

## 4. Ապրանքի տարբերակներ

### Ինչ են տարբերակները

Տարբերակը մեկ ապրանքի կոնկրետ չափս + գույն համադրությունն է։ Օրինակ՝ «Կարմիր շոր, M չափս» — մեկ տարբերակ է։ «Կարմիր շոր, L չափս» — այլ տարբերակ։ Յուրաքանչյուր տարբերակ ունի իր սեփական պաշարը (Մնացորդ), իր սեփական Խոտանի քանակը, և իր սեփական գինը։

### Կապը պատվերների և արտադրության հետ

Երբ հաճախորդը պատվիրում է մի ապրանք՝ պատվերը կապված է կոնկրետ տարբերակի հետ (ոչ թե ընդհանուր ապրանքին)։ Նույնը՝ արտադրությունները՝ Շարքի արտադրությունը միշտ կապված է մեկ կոնկրետ տարբերակին։

### Տարբերակի նորմալ ջնջում

Ապրանքի էջի տարբերակների աղյուսակում սեղմեք համապատասխան տողի **ջնջելու** կոճակը, ապա **«Confirm»**։

Եթե տարբերակը կապված է պատվերի կամ արտադրության հետ, համակարգը կհրաժարվի և ցույց կտա.
> «Չի կարող ջնջվել՝ կապված է **N** պատվերի հետ, **M** արտադրության հետ»

### Տարբերակի ուժով ջնջում

Մերժման դեպքում ադմինը կտեսնի **«Ուժով ջնջել»** կարմիր կոճակը՝ նույն տողի վրա։

Սեղմելիս բացվում է հաստատման պատուհան, որտեղ բացատրվում է՝ ինչ կկորսվի և ինչ կպահպանվի։ Շարունակելու համար մուտքագրեք `FORCE DELETE` և սեղմեք **«Ուժով ջնջել»**։

### Ինչ է լինում հին պատվերների և արտադրությունների հետ

Ուժով ջնջումից հետո՝

- **Հին պատվերները չեն հեռանում**։ Քանակը, գինը, ընդհանուր գումարը մնում են անփոփոխ։ Հաշվետվությունները ճիշտ կաշխատեն։
- Պատվերի տողում, ապրանքի անվան փոխարեն կտեսնեք **«(ջնջված)»** նշումը։ Օրինակ՝ «Կարմիր շոր (ջնջված) · M / Կարմիր»։
- Հին արտադրությունների մեջ՝ նույն կերպ։
- Պահեստի շարժերը պահպանվում են ամբողջությամբ։
- **Վաճառվող և Խոտանի պաշարը ՉԻ վերականգնվում** — ադմինը կարող է հետագայում ձեռքով կարգավորել։

### Ինչ նշանակում է «(ջնջված)» հին գրառումներում

Սա ցույց է տալիս, որ տվյալ տարբերակը, նյութը կամ կատեգորիան երբևէ եղել է, բայց ադմինը ուժով ջնջել է այն։ Կապված պատվերը, արտադրությունը, շարժը մնում են, որպեսզի՝

- Հաշվետվությունները ճիշտ համարակալվեն և գումարվեն։
- Աուդիտի մատյանը մնա ամբողջական։
- Հին հաճախորդը կարողանա տեսնել իր պատվերի պատմությունը։

## 5. Պահեստ / Նյութեր

### Նյութի ստեղծում

1. Անցեք **«Պահեստ»** բաժին։
2. Սեղմեք **«Ստեղծել նյութ»**։
3. Լրացրեք՝
   - **Անվանում** — օրինակ՝ «Կարմիր կտոր»։
   - **Արտիկուլ** (`SKU`) — եզակի կոդ։
   - **Չափման միավոր** — մետր, կիլոգրամ, հատ և այլն։
   - **Սկզբնական քանակ** — որքան կա պահեստում այս պահին։
   - **Ցածր մնացորդի շեմ** — որի տակ իջնելիս նյութը հայտնվի «Ցածր մնացորդ» հաշվետվությունում։
4. Սեղմեք **«Պահպանել»**։

### Նյութի խմբագրում

Նյութի տողում սեղմեք **«Խմբագրել»**։ Կարող եք փոխել անվանումը, սահմանը, նկարագրությունը։ Քանակը (Առկա քանակ) ևս կարող եք ճշգրտել ձեռքով — այս փոփոխությունը գրանցվում է պահեստի շարժերում որպես «adjustment» (ճշգրտում)։

### Առկա քանակ

Սա պահեստում տվյալ պահին առկա նյութի քանակն է։ Թարմացվում է ավտոմատ՝

- Երբ նոր արտադրություն եք ստեղծում (պակասում է)։
- Երբ տարբերակի մնացորդը մեծացնում եք (պակասում է)։
- Երբ պատվեր եք հաստատում, որը չի կատարվել պաշարից (պակասում է հումքի կողմից)։
- Երբ արտադրությունը ետ եք գցում (ավելանում է)։

### Ցածր մնացորդ

Եթե **Առկա քանակ** ≤ **Ցածր մնացորդի շեմ**, նյութը նշվում է կարմիր «Ցածր մնացորդ» պիտակով։ Նաև երևում է Վահանակի «Ցածր մնացորդ ունեցող ապրանքներ» թվում և «Ցածր մնացորդով նյութեր» հաշվետվությունում։

### Նյութի նորմալ ջնջում

Նյութի տողում սեղմեք **«Ջնջել»**։ Եթե նյութն ինչ-որ տեղ կապված է (բաղադրատոմս կամ պահեստի շարժ), համակարգը կհրաժարվի.
> «Հնարավոր չէ ջնջել. նյութը կապված է այլ գրառումների հետ»

### Նյութի ուժով ջնջում

Ուժով ջնջումը հնարավոր է **միայն եթե Առկա քանակ = 0**։ Սա կարևոր անվտանգության կանոն է — ադմինը չի կարող պատահաբար ջնջել այն նյութը, որի փաստացի մնացորդ կա պահեստում։

Քայլերը՝

1. Համոզվեք, որ նյութի **Առկա քանակը 0 է**։ Եթե չէ՝ նախ ճշգրտեք քանակը «Խմբագրել»-ով։
2. Նյութի տողում սեղմեք **«Ուժով ջնջել»**։
3. Հաստատման պատուհանում մուտքագրեք `FORCE DELETE`։
4. Սեղմեք **«Ուժով ջնջել»**։

### Ինչ է լինում պահեստի շարժերի պատմության հետ

Պահեստի շարժերը (հին գնումներ, արտադրության ծախսեր, ճշգրտումներ) **բոլորը պահպանվում են**։ Միայն նյութի կապը նվազ է դառնում NULL, իսկ նյութի անունը պահվում է որպես «`material_name_snapshot`»։

«Նյութերի օգտագործման հաշվետվությունում» հին շարժերը ցույց կտան նյութի անունը՝ «(ջնջված)» նշումով։

### Ինչ է լինում բաղադրատոմսերի հետ

Բոլոր այն ապրանքները, որոնց բաղադրատոմսում օգտագործվում էր այդ նյութը՝ ինքնաշխատ կհեռացնեն այդ կապը։ Կարող է անհրաժեշտ լինել խմբագրել ապրանքների բաղադրատոմսերը՝ նոր նյութ նշանակելու համար։

---

## 6. Կատեգորիաներ

Կատեգորիան օգնում է խմբավորել ապրանքները կատալոգում։ Օրինակ՝ «Շորեր», «Վերնաշապիկներ», «Տաբատներ»։

### Կատեգորիաների կառավարման բացում

«Ապրանքներ» էջի վերին աջում սեղմեք **«Կատեգորիաներ»** կոճակը։ Բացվում է կառավարման պատուհանը։

### Կատեգորիայի ստեղծում

Պատուհանի վերևի **«Նոր կատեգորիա»** դաշտում մուտքագրեք անվանումը, սեղմեք **«+ Ավելացնել»**։

### Դատարկ կատեգորիայի ջնջում

Կատեգորիայի «Ապրանքներ» սյունակում թիվը ցույց է տալիս, թե քանի ապրանք է պատկանում այդ կատեգորիային։ Եթե թիվը **0** է, աջում երևում է **«Ջնջել»** կոճակը։ Սեղմեք՝ կատեգորիան ընդմիշտ կհեռանա։

### Կատեգորիայի ուժով ջնջում

Եթե կատեգորիան ունի ապրանքներ (օրինակ՝ 5), աջում երևում է կարմիր նշում.
> «Կապված է 5 ապրանքի հետ»  
> **«Ուժով ջնջել»**

Սեղմելիս բացվում է հաստատման պատուհան։ Մուտքագրեք `FORCE DELETE`, հաստատեք։

### Ի՞նչ է լինում ապրանքների հետ

- **Ապրանքները ՉԵՆ ջնջվում**։
- Բոլոր ապրանքները, որոնք պատկանում էին այս կատեգորիային, դառնում են **«առանց կատեգորիայի»**։
- Կարող եք հետագայում խմբագրել յուրաքանչյուր ապրանքը և նշանակել նոր կատեգորիա։

---

## 7. Պատվերներ

### Պատվերի ստեղծում

1. Անցեք **«Պատվերներ»** բաժին։
2. Սեղմեք **«Ստեղծել պատվեր»**։
3. Ընտրեք **հաճախորդը**։
4. Ընտրեք **կարևորությունը** (Ցածր / Նորմալ / Բարձր / Շտապ)։
5. Մուտքագրեք **վերջնաժամկետը** (ընտրովի)։
6. Ավելացրեք **տողեր** — ապրանքի տարբերակը, քանակը, գինը (մեկ միավորի համար)։
7. Սեղմեք **«Պահպանել»**։

### Տողեր ավելացնելը

Մեկ պատվերը կարող է ունենալ բազմաթիվ տողեր։ Յուրաքանչյուր տող մեկ տարբերակի կոնկրետ քանակն է։

> Համակարգն ինքնաշխատ ստուգում է, արդյոք պաշարը բավարար է։ Եթե բավարար չէ, պատվերը կհաստատվի «չհաստատված» վիճակում, իսկ ադմինը կարող է ստեղծել արտադրություն այդ մասի համար։

### Կարգավիճակի փոփոխում

Պատվերի էջում սեղմեք կարգավիճակի կոճակները՝

- **Սևագիր** → **Հաստատված** → **Ավարտված**։

Հաստատելու պահին համակարգը՝

- Նվազեցնում է վաճառվող պաշարը այն մասի համար, որը կա արդեն պաշարում։
- Մնացած մասը մատնանշում է որպես «արտադրության կարիք»։

### Պատվերի նորմալ ջնջում

Պատվերի տողում սեղմեք **«Ջնջել»**։ Համակարգը կհրաժարվի, եթե՝

- Պատվերի համար արդեն կտրվել է պաշարը (`order_stock_already_deducted`)։
- Պատվերի որևէ արտադրության փուլ արդեն սկսվել է (`order_has_active_production`)։

Սովորական ջնջումը հաջողվում է միայն այն դեպքում, երբ պատվերը դեռևս սևագիր է, պաշարը չի կտրվել, և բոլոր արտադրության փուլերը դեռ «Սպասման մեջ» են։

### Պատվերի ուժով ջնջում

Ադմինի համար մերժման դեպքում երևում է **«Ուժով ջնջել»** կոճակը։ Հաստատման պատուհանում մուտքագրեք `FORCE DELETE`։

### Ինչ է լինում պահեստի շարժերի և արտադրության փուլերի հետ

- Պատվերն ընդմիշտ հեռանում է, բայց **պահեստի շարժերը** մնում են։ Այսինքն, եթե պատվերի համար նյութ էր կտրվել, ապա այդ ճակատագիրը երևում է որպես «adjustment» տեսակի շարժ՝ առանց պատվերի կապի։
- Պատվերին պատկանող **արտադրության փուլերը** ջնջվում են։
- **Աուդիտի մատյանը** գրանցում է գործողությունը։

### Երբ պետք է օգտագործել ուժով ջնջելը

Միայն այն դեպքերում, երբ՝

- Պատվերը սխալ է ստեղծվել։
- Տվյալներ ստուգելու / փորձարկման համար ստեղծված է եղել։
- Հաճախորդն ընդհանուր հրաժարվել է, և բիզնեսի որոշումը՝ ընդմիշտ հեռացնել։

Չպետք է օգտագործել՝ եթե պարզապես ուզում եք «մաքրել» հին պատվերները։ Դրանք պետք են հաշվետվությունների համար։

---

## 8. Արտադրություն

Համակարգում կան երկու տեսակի արտադրություններ՝

### 1. Պատվերի արտադրության փուլեր

Երբ պատվեր է հաստատվում, ստեղծվում են 5 փուլ՝

1. **Կտրում**
2. **Մշակում** (կարման)
3. **Որակի վերահսկում**
4. **Փաթեթավորում**
5. **Պատրաստ է առաքման**

Յուրաքանչյուր փուլի կարգավիճակը՝ Սպասման մեջ → Ընթացքի մեջ → Ավարտված։

Արտադրության էջում մեկ պատվերի համար ցույց է տրվում միայն մեկ տող, որը ներկայացնում է ընթացիկ ակտիվ փուլը։

### 2. Պահեստի համար արտադրություններ (Շարք)

Սա պաշարը լրացնելու համար ստեղծվող արտադրությունն է՝ առանց կոնկրետ պատվերի։ Արտադրելու համար ադմինը՝

1. Անցնում է **«Արտադրություն»** էջ։
2. Սեղմում է **«Ստեղծել արտադրություն»**։
3. Ընտրում է ապրանք + տարբերակ + արտադրելու քանակը։
4. Համակարգը հաշվում է, թե որքան նյութ պետք կլինի, և **նվազեցնում է պահեստից** այդ քանակը։
5. Ստեղծվում է արտադրությունը՝ «Կտրում» փուլում, «Սպասման մեջ» կարգավիճակում։

### Արտադրությունների ավարտում

Ընթացքում ադմինը կարող է մասնակի լրացնել արտադրությունը՝ նշելով քանի «Լավ» (վաճառելի) և քանի «Խոտան» միավոր է ստացվել։ Երբ Լավ + Խոտան = Արտադրվող քանակ, արտադրությունը դառնում է «Ավարտված», և՝

- Վաճառվող պաշարը ավելանում է Լավ քանակով։
- Խոտանի պաշարը ավելանում է Խոտանի քանակով։

### Արտադրության նորմալ ջնջում (Ետ վերցնել)

Միայն **ավարտված** արտադրությունների համար։ Ադմինի համար ցույց է տրվում **«Ջնջել»** կոճակը։ Սեղմելիս՝

- Հումքը վերադարձվում է պահեստ։
- Վաճառվող պաշարը նվազեցվում է։
- Խոտանի պաշարը նվազեցվում է։
- Արտադրությունը հեռանում է։

Համակարգը կհրաժարվի, եթե՝

- Պաշարի մի մասը արդեն վաճառվել է (`batch_rollback_would_underflow`)։

### Արտադրության ուժով ջնջում

Ադմինի համար ցույց է տրվում **«Ուժով ջնջել»** կոճակը **ցանկացած** արտադրության համար (Սպասման, Ընթացքի, Ավարտված)։ Դա Universal escape — ստիպում է հեռացնել արտադրությունը, անգամ եթե կապված է պաշարի շարժերի հետ։

### Ետ վերցնելու ջնջում vs. Ուժով ջնջում

| | Նորմալ ջնջում | Ուժով ջնջում |
|---|---|---|
| Հումքը վերադարձվու՞մ է պահեստ | Այո | **Ոչ** |
| Վաճառվող պաշարը նվազեցվու՞մ է | Այո | **Ոչ** |
| Խոտանի պաշարը նվազեցվու՞մ է | Այո | **Ոչ** |
| Աշխատու՞մ է անավարտ արտադրությունների համար | Ոչ | **Այո** |
| Աշխատու՞մ է, եթե պաշարի մի մասը վաճառվել է | Ոչ | **Այո** |

### ԶԳՈՒՇՈՒԹՅՈՒՆ. Ուժով ջնջում չի վերականգնում նյութերը

Կարևոր է հասկանալ. եթե արտադրությունից արդեն կտրվել է հումք, ուժով ջնջումը **չի վերադարձնում** այդ հումքը պահեստ։ Փաստացիորեն հումքը կարող է լինել արդեն ֆիզիկապես կտրված, կարված, օգտագործված։ Ադմինը պետք է ինքնուրույն որոշի, արդյոք հետագայում ձեռքով ճշգրտել պահեստի մնացորդը։

---

## 9. Հաճախորդներ

### Հաճախորդի ստեղծում

1. Անցեք **«Հաճախորդներ»** բաժին։
2. Սեղմեք **«Ստեղծել հաճախորդ»**։
3. Լրացրեք՝
   - **Անվանում** — հաճախորդի լրիվ անուն կամ ընկերության պատասխանատու անձ։
   - **Ընկերության անվանում** — ընտրովի։
   - **`Email`** — հաճախորդի կոնտակտը։ Հանդիսանում է եզակի։
   - **Հեռախոս** — ընտրովի։
   - **Հասցե** — ընտրովի։
   - **Զեղչի տոկոս** — եթե հաճախորդն ունի մշտական զեղչ։
4. Սեղմեք **«Պահպանել»**։

### Հաճախորդի խմբագրում

Հաճախորդի էջում սեղմեք **«Խմբագրել»**։ Բոլոր դաշտերը կարող եք փոխել։

### Հաճախորդի արխիվացում / ջնջում

Հաճախորդի էջում սեղմեք **«Ջնջել»**։ Հաճախորդը կարխիվացվի (անակտիվ կդառնա)։ Կարող եք հետագայում նորից ակտիվացնել խմբագրման էջից։

### Պատմական պատվերները մնում են

Արխիվացված հաճախորդի **բոլոր պատվերները, պատմությունը և հաշվետվությունները պահպանվում են**։ Միայն հաճախորդը նոր պատվեր ստեղծելու համար անհասանելի է դառնում։ Հաշվետվությունները շարունակում են ճիշտ ցույց տալ նրա անունով եկամուտները։

> Հաճախորդի համար **Ուժով ջնջել** տարբերակ չկա — դա կարող է կոտրել պատմական պատվերները։ Արխիվացումը բավարար է։

---

## 10. Օգտատերեր

### Օգտատերի ստեղծում

1. Անցեք **«Օգտատերեր»** բաժին։
2. Սեղմեք **«Ստեղծել օգտատեր»**։
3. Մուտքագրեք`Email`-ը, ժամանակավոր գաղտնաբառը։
4. Ընտրեք **դերը**։
5. Եթե դերը **«Օգտատեր»** է, ընտրեք համապատասխան հաճախորդը (օգտատերը կկարողանա մուտք գործել միայն իր հաճախորդի տվյալներին)։
6. Սեղմեք **«Պահպանել»**։

### Դերեր

| Դեր | Իրավասություն |
|---|---|
| **Ադմին** | Բոլոր բաժինների լրիվ կառավարում, ներառյալ ուժով ջնջումները։ |
| **Տնօրեն** | Ապրանքներ, պատվերներ, արտադրություն, հաճախորդներ, հաշվետվություններ, Ադմինից բացի օգտատերերի ստեղծում (միայն «Օգտատեր» դերով)։ |
| **Արտադրության ղեկավար** | Պատվերներ, արտադրություն, ապրանքի տեսք, պահեստի տեսք։ |
| **Պահեստապետ** | Պահեստի լրիվ կառավարում (նյութեր, շարժեր, քանակների ճշգրտում)։ |
| **Օգտատեր** | Միայն իր սեփական պատվերները և կատալոգը։ |

### Օգտատերի ակտիվացում/ապակտիվացում

Օգտատերի տողում սեղմեք **«Ապակտիվացնել»**։ Հաստատման պատուհանում սեղմեք **«Հաստատել»**։ Օգտատերը այլևս չի կարող մուտք գործել։ Հետագայում նորից ակտիվացնելու համար նույն գործողությունը կդառնա **«Վերակտիվացնել»**։

### Ինչու վերջին ակտիվ ադմինը չի կարող ապակտիվացվել

Համակարգում միշտ պետք է լինի առնվազն մեկ ակտիվ ադմին։ Հակառակ դեպքում ոչ ոք չի կարողանա կառավարել համակարգը — ստեղծել նոր ադմին, փոխել դերեր, թարմացնել կարգավորումներ։

Եթե փորձեք ապակտիվացնել կամ իջեցնել միակ ակտիվ ադմինին, համակարգը կհրաժարվի՝ ցույց տալով.
> «Last active admin required»

**Լուծումը**. նախ ստեղծեք նոր ադմին (կամ բարձրացրեք գործող օգտատերին մինչև ադմին), հետո ապակտիվացրեք հները։

### Ինքն իրեն չի կարող փոխել

Ադմինը չի կարող՝

- Փոխել **իր սեփական դերը**։
- **Ապակտիվացնել ինքն իրեն**։

Սա ուղղված է պաշտպանելու համակարգին պատահական արգելափակումից։

## 11. Հաշվետվություններ

«Հաշվետվություններ» էջում ադմինը կարող է ստեղծել տարբեր տիպի հաշվետվություններ, դիտել արդյունքները էկրանին, և արտահանել CSV ձևաչափով։

### Հաշվետվության տեսակները

| Հաշվետվություն | Ինչ է ցույց տալիս |
|---|---|
| **Պատվերների հաշվետվություն** | Բոլոր պատվերները ընտրված ժամանակահատվածում՝ կարգավիճակով, կարևորությամբ, ընդհանուր գումարով, ստեղծման ամսաթվով, վերջնաժամկետով։ |
| **Վաճառքների հաշվետվություն** | Ընդհանուր եկամուտը, օրական եկամուտը, եկամուտ ըստ հաճախորդի, պատվերի ապրանքների մանրամասները։ Կարող եք զտել ըստ կոնկրետ հաճախորդի, և ապա՝ ըստ կոնկրետ պատվերի։ |
| **Պահեստի հաշվետվություն** | Բոլոր նյութերը՝ Առկա քանակ, Նվազագույն, Ցածր մնացորդի դրոշակ։ |
| **Նյութերի օգտագործման հաշվետվություն** | Պահեստի շարժերը՝ նյութ, քանակի փոփոխություն, պատճառ, ամսաթիվ, ադմին։ Աշխատում է նաև ուժով ջնջված նյութերի համար՝ «(ջնջված)» նշումով։ |
| **Արտադրության հաշվետվություն** | Պատվերի արտադրության փուլերը, Փուլ, Կարգավիճակ, սկսման և ավարտի ամսաթիվ։ |
| **Ցածր մնացորդով նյութեր** | Միայն այն նյութերը, որոնց Առկա քանակ ≤ Նվազագույն շեմ։ |
| **Հաճախորդների զեղչերի հաշվետվություն** | Հաճախորդները՝ Email, Անվանում, Զեղչի տոկոս, Պատվերներ, Եկամուտ։ |
| **Խոտանի հաշվետվություն** | Տարբերակները, որոնք ունեն Խոտանի պաշար > 0։ |

### CSV արտահանում

Արդյունքը ստեղծելուց հետո սեղմեք **«Արտահանել CSV»** — ֆայլը կներբեռնվի ձեր համակարգչի վրա։ Կարող եք բացել Excel-ով կամ այլ ծրագրով։

### Ինչ նշանակում է «(ջնջված)» հաշվետվությունում

Եթե հաշվետվությունում տեսնում եք «(ջնջված)» նշումով անվանում՝ դա նշանակում է, որ այդ նյութը, ապրանքը կամ տարբերակը երբևէ եղել է, ադմինն ուժով ջնջել է, բայց պատմական գրառումը պահպանվել է հաշվետվության ճշտության համար։

Օրինակ՝ «Կարմիր կտոր (ջնջված)» նշանակում է, որ այդ նյութը ուժով ջնջվել է, բայց հին արտադրությունների ժամանակ օգտագործվել է, և շարժի պատմությունը մնում է։

## 12. Գործողությունների պատմություն

«Գործողությունների պատմություն» էջը ադմինի համար ամենակարևոր աուդիտի գործիքն է։ Այստեղ արձանագրվում են համակարգում կատարված **բոլոր կարևոր գործողությունները**։

### Ինչ է գրանցվում

- Մուտք / Ելք / Մուտքի սխալներ։
- Օգտատերերի ստեղծում, փոփոխում, ապակտիվացում, դեր փոխում, գաղտնաբառի փոփոխում։
- Հաճախորդներ — ստեղծում, խմբագրում, արխիվացում։
- Կատեգորիաներ — ստեղծում, խմբագրում, ջնջում, **ուժով ջնջում**։
- Ապրանքներ — ստեղծում, խմբագրում, արխիվացում, **ուժով ջնջում**։
- Տարբերակներ — ստեղծում, խմբագրում, ջնջում, **ուժով ջնջում**։
- Նյութեր — ստեղծում, խմբագրում, ջնջում, **ուժով ջնջում**։
- Պահեստի շարժեր։
- Պատվերներ — ստեղծում, փոփոխում, ջնջում, **ուժով ջնջում**, տողի ավելացում/հեռացում, կարգավիճակի փոփոխում։
- Արտադրություններ — ստեղծում, փուլի փոփոխում, ավարտում, ջնջում, **ուժով ջնջում**։
- Հաշվետվությունների ստեղծում և արտահանում։

### Ուժով ջնջելու գրառումներ — կարմիր պիտակ

Ուժով ջնջման գրառումները հատուկ նշվում են։ Տողը ունի **թեթևակի կարմիր ֆոն**, իսկ գործողության կողքին երևում է **կարմիր «Ուժով»** պիտակ։ Դա հնարավորություն է տալիս ադմինին արագ նկատել՝ կա արդյոք ուղի մուտքագրված անդարձելի գործողություն։

### Ֆիլտրեր

Կարելի է ֆիլտրել՝

- **Մոդուլ** — միայն Պատվեր / Ապրանք / Նյութ և այլն։
- **Գործողություն** — կոնկրետ տիպի, օրինակ՝ `order.created`։
- **Օգտատեր `ID`** — միայն այս օգտատերի գործողությունները։
- **Ամսաթվային միջակայք** — սկզբից մինչև վերջ։

### Աուդիտի մատյանը երբեք չի ջնջվում

Կարևորագույն կանոն. աուդիտի գրառումները **երբեք չեն ջնջվում**, անգամ ադմինի կողմից, անգամ ուժով։ Դա ապահովում է՝

- Համակարգի ապահովությունը։
- Հնարավորությունը՝ բացահայտել, թե ով, երբ, ինչ արեց։
- Հարկային և ֆինանսական հաշվետվությունների ճշտությունը։

Եթե կասկածում եք, որ ինչ-որ բան սխալ է գնում, առաջին հերթին նայեք գործողությունների պատմությունը։

---

## 13. Ուժով ջնջելու կանոններ

Սա հատուկ բաժին է, որը ամփոփում է «Ուժով ջնջելու» (Force Delete) բոլոր կանոնները։

### Ընդհանուր կանոններ

- **Ուժով ջնջելը հասանելի է միայն ադմինին**։ Մյուս դերերը նույնիսկ կոճակը չեն տեսնում։
- **Պահանջում է հաստատման մուտքագրել `FORCE DELETE` տեքստը**։ Այլ ձև, օրինակ՝ «Force Delete» կամ «force delete», չի աշխատի։ Մուտքագրումը պետք է լինի մեծատառերով, ճիշտ այնպես, ինչպես ցույց է տրված մոդալում։
- **Անդարձելի է**։ Ուժով ջնջված տվյալը հնարավոր չէ վերականգնել։
- **Պահպանում է պատմությունը այնքանով, որքանով հնարավոր է**։ Կապված պատվերները, շարժերը, արտադրությունները չեն ջնջվում — դրանք միայն կորցնում են կապը ջնջվածի հետ։
- **Մաքրում է անհարկի կապերը**։ Որոշ մետատվյալներ (օրինակ՝ բաղադրատոմսերը, որոնք օգտագործում են ջնջվող նյութը) ինքնաշխատ հեռանում են։
- **Գրանցում է աուդիտի գրառում**։ Ադմինի անունով, ամսաթվով, մանրամասներով։

### Էնտիտիների աղյուսակ

| Տեսակ | Նորմալ ջնջում | Ուժով ջնջում | Ինչ է պահպանվում |
|---|---|---|---|
| **Նյութ** | Մերժում, եթե կապված է բաղադրատոմսերի կամ շարժերի հետ | Հնարավոր է **միայն Առկա քանակ = 0** | Պահեստի շարժերի պատմությունը՝ «(ջնջված)» նշումով |
| **Ապրանք** | Արխիվացում (անակտիվ) | Ադմինի համար՝ պահանջում է **զրո տարբերակ + զրո արտադրություն** | Հին պատվերները ընդհանուր մնում են այնքան, որքան տարբերակները կամ պատվերը հղում չեն տալիս |
| **Տարբերակ** | Մերժում, եթե կապված է պատվերի կամ արտադրության հետ | Ադմինի համար՝ **առանց պայման** (universal escape) | Հին պատվերներ, արտադրություններ, շարժեր — «(ջնջված)» նշումով |
| **Արտադրություն (Շարք)** | Միայն ավարտված, պաշարը ետ վերցնելով | Ադմինի համար՝ ցանկացած փուլում, **առանց պաշարի վերականգնման** | Կապված պահեստի շարժերը (batch_id-ն NULL) |
| **Պատվեր** | Միայն եթե պաշարը չի կտրվել և բոլոր փուլերը սպասման մեջ են | Ադմինի համար՝ ցանկացած կարգավիճակում | Աուդիտի գրառումները, պահեստի շարժերը (առանց պատվերի կապի) |
| **Կատեգորիա** | Հնարավոր է **միայն եթե կատեգորիան դատարկ է** | Ադմինի համար՝ ապրանքների կատեգորիան դառնում է NULL | Ապրանքները՝ ամբողջությամբ |

## 14. Անվտանգ աշխատանքի օրինակներ

Ստորև բերված են ամենահաճախ կիրառվող սցենարները՝ քայլ-առ-քայլ հրահանգներով։

### A. Սխալ ստեղծված նյութի հեռացում

**Իրավիճակ**. Ստեղծել եք նյութ, որը պետք չէ, և Առկա քանակ-ը 0 է (կամ դեռ չեք ճշգրտել)։

**Քայլեր**.

1. **«Պահեստ»** էջում գտեք նյութը։
2. Համոզվեք, որ Առկա քանակը 0 է։ Եթե չէ՝ սեղմեք **«Խմբագրել»**, փոխեք քանակը 0։
3. Սեղմեք **«Ջնջել»**։
   - Եթե նյութը միայն դատարկ ստեղծված է եղել, ջնջումը հաջողվում է։
   - Եթե համակարգը մերժում է («Հնարավոր չէ ջնջել. նյութը կապված է...»), ապա կա շարժի կամ բաղադրատոմսի կապ։ Անցեք քայլ 4-ին։
4. Սեղմեք նյութի կողքին գտնվող **«Ուժով ջնջել»** կարմիր կոճակը։
5. Հաստատման պատուհանում մուտքագրեք `FORCE DELETE` և սեղմեք **«Ուժով ջնջել»**։

**Արդյունք**. նյութը հեռացվում է։ Հին շարժերը մնում են «(ջնջված)» նշումով։

### B. Սխալ ապրանքի հեռացում, որն ունի տարբերակներ

**Իրավիճակ**. Ստեղծել եք ապրանք, պարզվեց որ պետք չէ։ Արդեն ավելացրել եք տարբերակներ։

**Քայլեր**.

1. **«Ապրանքներ»** էջում գտեք ապրանքը, անցեք ապրանքի էջ։
2. **Ապրանքը նախ արխիվացրեք** — սեղմեք **«Ջնջել»**։ Կարգավիճակը կդառնա «Անակտիվ»։
3. Տարբերակների աղյուսակում, յուրաքանչյուր տարբերակի համար՝
   - Սեղմեք ջնջելու կոճակը։
   - Եթե տարբերակը կապված չէ պատվերի կամ արտադրության հետ, ջնջումը հաջողվում է։
   - Եթե կապված է, սեղմեք **«Ուժով ջնջել»**, մուտքագրեք `FORCE DELETE`, հաստատեք։
4. Ապահովեք, որ բոլոր տարբերակները հեռանան։
5. Վերադարձեք **«Ապրանքներ»** էջ, գտեք ապրանքի տողը։
6. Սեղմեք ապրանքի կողքի **«Ուժով ջնջել»** կոճակը (պայմանը՝ զրո տարբերակ + զրո արտադրություն)։
7. Հաստատման պատուհանում մուտքագրեք `FORCE DELETE`, հաստատեք։

**Արդյունք**. ապրանքը, նկարները, բաղադրատոմսերը — բոլորը հեռանում են։ Հին պատվերները մնում են «(ջնջված)» նշումով։

### C. Սխալ տարբերակի հեռացում, որն օգտագործվել է պատվերի մեջ

**Իրավիճակ**. Հաճախորդը պատվիրել է «Կարմիր շոր / M», բայց պարզվեց որ իրականում նա ուզում էր «Կարմիր շոր / L»։ Արդեն ստեղծեցիք տարբերակը, պատվերի մեջ ավելացրեցիք։ Հիմա սխալ տարբերակը ուզում եք ընդհանուր հեռացնել։

**Քայլեր**.

1. Նախ ուղղեք պատվերը. անցեք պատվերի էջ, փոխեք տողը՝ ճիշտ տարբերակին։
2. Անցեք ապրանքի էջ։
3. Տարբերակների աղյուսակում սեղմեք «Կարմիր / M»-ի ջնջելու կոճակը։
4. Համակարգը կհայտնի՝ «Չի կարող ջնջվել՝ կապված է **N** պատվերի հետ»։
5. Դա տեղի է ունենում, քանի որ պատվերի պատմությունում տարբերակը դեռ կա։ Ադմինը կարող է **«Ուժով ջնջել»**։
6. Մուտքագրեք `FORCE DELETE`, հաստատեք։

**Արդյունք**. տարբերակն ընդմիշտ հեռանում է։ Բոլոր այն հին պատվերները, որտեղ նա օգտագործվել էր, շարունակում են ցույց տալ ճիշտ քանակն ու գումարը, բայց ապրանքի անվան փոխարեն երևում է «Կարմիր շոր (ջնջված) · M / Կարմիր»։ Հաշվետվությունները ճիշտ կաշխատեն։

### D. Սխալ արտադրության հեռացում

**Իրավիճակ**. Սխալ էիք ստեղծել արտադրությունը՝ սխալ քանակով։ Արդեն կտրվել է հումք պահեստից։

**Քայլեր (եթե արտադրությունը դեռ ավարտված չէ)**.

1. **«Արտադրություն»** էջում գտեք արտադրությունը։
2. Սեղմեք **«Ուժով ջնջել»** կարմիր կոճակը։
3. Հաստատման պատուհանում նկատեք. «Հումքը ՉԻ վերադարձվի պահեստ»։
4. Մուտքագրեք `FORCE DELETE`, հաստատեք։
5. **Ձեռքով ճշգրտեք պահեստը** — անցեք **«Պահեստ»**, գտեք օգտագործված նյութերը, սեղմեք **«Խմբագրել»**, ճշգրտեք Առկա քանակը։ Համակարգը կգրանցի «adjustment» շարժ։

**Քայլեր (եթե արտադրությունը ավարտված է, և պաշարը դեռ չի վաճառվել)**.

1. Արտադրության կողքին սեղմեք **«Ջնջել»** (ոչ թե «Ուժով ջնջել»)։
2. Հաստատման պատուհանում նկատեք, որ պաշարը կվերականգնվի։
3. Սեղմեք **«Ջնջել»**։

**Արդյունք**. (նորմալ դեպքում) ամեն ինչ վերականգնվում է, ինչպես եղել է մինչ արտադրությունը։

### E. Սխալ կատեգորիայի հեռացում

**Իրավիճակ**. Կատեգորիան չի կարող մնալ (օրինակ՝ սխալ ուղղագրությամբ ստեղծվել է)։

**Քայլեր**.

1. **«Ապրանքներ»** էջում սեղմեք **«Կատեգորիաներ»**։
2. Գտեք սխալ կատեգորիան։
3. Եթե «Ապրանքներ» սյունակում 0 է՝ սեղմեք **«Ջնջել»**։
4. Եթե թիվը > 0՝ սեղմեք **«Ուժով ջնջել»**։ Մուտքագրեք `FORCE DELETE`, հաստատեք։
5. Ապրանքները դառնում են «առանց կատեգորիայի»։ Անցեք յուրաքանչյուրի էջ և սահմանեք ճիշտ կատեգորիա։

### F. Թեստի կամ սխալ տվյալների ընդհանուր մաքրում

**Իրավիճակ**. Կարգավորելու ընթացքում ստեղծել եք բազմաթիվ թեստային տվյալներ՝ պատվերներ, ապրանքներ, հաճախորդներ։ Ուզում եք ընդհանուր մաքրել։

**Հնարավորությունները** (պատվիրակում)՝

1. **Հաճախորդներ** — արխիվացրեք (չեն մաքրվում, բայց անակտիվ կդառնան)։
2. **Պատվերներ** — եթե դեռ սևագիր են, սեղմեք **«Ջնջել»**։ Հաստատվածների համար օգտագործեք **«Ուժով ջնջել»**։
3. **Արտադրություններ** — **«Ուժով ջնջել»**։
4. **Ապրանքներ** — նախ արխիվացրեք, ապա հեռացրեք տարբերակները, ապա ուժով ջնջեք ապրանքները (տես օրինակ B)։
5. **Նյութեր** — ճշգրտեք քանակը 0-ի, ապա ուժով ջնջեք (տես օրինակ A)։
6. **Կատեգորիաներ** — ուժով ջնջեք (տես օրինակ E)։

> **Կարևոր**. Հաճախորդների և օգտատերերի համար Ուժով ջնջել չկա — միայն արխիվացում։ Աուդիտի մատյանը նույնպես չի ջնջվում։

## 15. Հաճախակի հանդիպող խնդիրներ

### «Հնարավոր չէ ջնջել. ... կապված է ...»

**Նշանակում է**. այն բանը, ինչ փորձում եք ջնջել, ինչ-որ տեղ է օգտագործվում։ Համակարգը պաշտպանում է ձեզ պատահական կորստից։

**Լուծում**. Կարդացեք հաղորդագրությունը — ասված է, թե քանի և ինչ կապ կա։ Հետո՝

- **Կամ** կտրեք կապը (օրինակ՝ խմբագրեք պատվերը)։
- **Կամ** եթե ադմին եք և կապը պետք չէ — սեղմեք **«Ուժով ջնջել»**։

### «Quantity is not zero» / «Հնարավոր չէ ուժով ջնջել. քանակը 0 չէ»

**Նշանակում է**. փորձում եք ուժով ջնջել նյութ, որի **Առկա քանակը** տակավին > 0։

**Լուծում**. Անցեք **«Պահեստ»** → գտեք նյութը → **«Խմբագրել»** → ճշտեք քանակը 0։ Հետո կրկին փորձեք ուժով ջնջել։

### «Last active admin required»

**Նշանակում է**. փորձում եք ապակտիվացնել կամ իջեցնել միակ ակտիվ ադմինին։

**Լուծում**. Նախ ստեղծեք նոր ադմին (կամ բարձրացրեք առկա օգտատերին մինչև ադմին)։ Ապա կրկին փորձեք։

### Գրառման մեջ երևում է «(ջնջված)»

**Նշանակում է**. այդ նյութը, ապրանքը, տարբերակը կամ կատեգորիան երբևէ եղել է, բայց ադմինը (հնարավոր է, դուք ինքներդ) ուժով ջնջել է այն։ Պատմությունը պահպանվել է, որպեսզի հաշվետվությունները չխախտվեն։

**Գործողություն**. Ոչ մի։ Սա սպասվող, ճիշտ պահվածք է։ Եթե ուզում եք իմանալ, թե ով և երբ է ջնջել, անցեք **«Գործողությունների պատմություն»** և ֆիլտրեք ըստ համապատասխան մոդուլի։

### «Չեմ տեսնում բոլոր նյութերի տողերը պահեստում»

**Նշանակում է**. ցանկը էջակալված է — մեկ էջում երևում է մինչև 20 տող։

**Լուծում**. Աղյուսակի ներքևում սեղմեք **«Next»** (Հաջորդ), կամ URL-ում ձեռքով փոխեք `page=2`, `page=3` և այլն։ Որոնման դաշտում կարող եք նաև մուտքագրել նյութի անվան մի մաս՝ արագ գտնելու համար։

### «Ուժով ջնջել» կոճակը չեմ տեսնում

**Հնարավոր պատճառները**.

- Դուք ադմին չեք։ Միայն **«Ադմին»** դերը տեսնում է այս կոճակը։ Մյուս դերերում (Տնօրեն, Արտադրության ղեկավար, Պահեստապետ, Օգտատեր) կոճակը չի երևում։
- Ապրանքի համար — ապրանքը արխիվացված չէ, կամ ունի տարբերակներ։ Արխիվացրեք և մաքրեք տարբերակները։
- Նյութի համար — Առկա քանակը 0 չէ։
- Պատվերի համար — դուք պետք է լինեք ադմին, և տեսանելի կլինի անգամ եթե նորմալ ջնջումը հաջողվում է։

### Հաշվետվությունում երևում է ջնջված նյութ / ապրանք / տարբերակ

**Նշանակում է**. դա սպասվող պահվածք է։ Հաշվետվությունը պետք է ճշգրիտ լինի՝ նույնիսկ ուժով ջնջումից հետո։ Անվանումը կպահպանվի «(ջնջված)» նշումով։ Թիվերը, գումարները, քանակները կմնան ճշգրիտ։

## 16. Անվտանգության կարևոր նշումներ

1. **Ուժով ջնջելը մի օգտագործեք ամենօրյա մաքրման համար**, եթե բացարձակ անհրաժեշտություն չկա։ Կա ռիսկ՝ ընդմիշտ կորցնել կարևոր կապեր, որոնք հետագայում անհրաժեշտ կլինեն աուդիտի, հարկային հաշվետվությունների, պաշարների վերլուծության համար։

2. **Նախընտրեք արխիվացում, որտեղ հնարավոր է**։ Հաճախորդները, օգտատերերը, ապրանքները բոլորն ունեն արխիվացման տարբերակ։ Արխիվացված տարրը դառնում է անակտիվ, բայց պատմությունը մնում է ամբողջական։

3. **Ուժով ջնջելը կիրառեք միայն**`-ի համար՝
   - սխալ ստեղծված տվյալներ,
   - թեստավորման ընթացքում մնացած տվյալներ,
   - հաճախորդի կամ ղեկավարի հաստատմամբ ընդհանուր մաքրման համար։

4. **Հաշվետվությունները և պատմությունը պահպանվում են**, բայց ուժով ջնջումից հետո կարող են ցույց տալ «(ջնջված)» նշումներ։ Սա բնականոն երևույթ է, ոչ թե սխալ։

5. **Աուդիտի մատյանը ոչ ոք չի կարող ջնջել**, ոչ նույնիսկ ադմինը։ Ուժով ջնջման բոլոր գործողությունները հավերժ պահպանվում են որպես կարմիր նշումով տողեր «Գործողությունների պատմություն» էջում։

6. **Մինչ ուժով ջնջելը, համոզվեք, որ ձեռքի տակ ունեք այն տեղեկատվությունը, որը հնարավոր չէ հետագայում վերականգնել**։ Օրինակ՝ եթե ապրանքի նկարներ կան, որոնք ուզում եք պահել, ներբեռնեք դրանք առանձին։

7. **Միշտ կարդացեք հաստատման պատուհանի բոլոր կետերը**, մինչ `FORCE DELETE` մուտքագրելը։ Այնտեղ բացատրված է, թե ինչը կկորսվի անդարձելիորեն, և ինչը կպահպանվի որպես «(ջնջված)»։

8. **Ուժով ջնջումից առաջ խորհրդակցեք** — եթե կասկածներ ունեք, խորհրդակցեք ձեր ղեկավարի, պահեստապետի, կամ արտադրության ղեկավարի հետ։ Անդարձելի գործողություն է — մի շտապեք։

## 17. Վերջնական ստուգաթերթ

### Ուժով ջնջելուց առաջ

- [ ] Դա ի՞նչ տեսակ գործողություն է — սխալ տվյալի մաքրում, թե իրական աշխատանքային գործողություն։
- [ ] Արդյո՞ք կա այլ ճանապարհ — արխիվացում, խմբագրում, ճշգրտում։
- [ ] Արդյո՞ք ձեռքի տակ ունեմ կրկնօրինակներ կամ տեղեկություններ, որոնք հետագայում անհրաժեշտ կլինեն (նկարներ, փաստաթղթեր)։
- [ ] Հաստատման պատուհանում կարդացե՞լ եմ, թե ինչ կկորսվի և ինչ կպահպանվի։
- [ ] Արդյո՞ք պահպանվելու են պատվերները, շարժերը, հաշվետվությունները, որոնք պետք են։
- [ ] Մյուս կողմի մարդիկ՝ պահեստապետ, արտադրության ղեկավար, ղեկավարություն, գիտե՞ն այս գործողության մասին (եթե անհրաժեշտ է)։

### Ուժով ջնջելուց հետո

- [ ] Հաջողության հաղորդագրությունը տեսնո՞ւմ եմ։
- [ ] Տեսնում եմ արդյո՞ք ցանկում, որ տվյալը հեռացել է։
- [ ] «Գործողությունների պատմություն» էջում տեսնում եմ արդյո՞ք իմ կողմից ուժով ջնջման կարմիր նշումով տող։
- [ ] Անհրաժեշտության դեպքում ճշգրտել եմ պահեստի մնացորդը (արտադրության ուժով ջնջումից հետո)։
- [ ] Անհրաժեշտության դեպքում նշանակել եմ նոր կատեգորիա ապրանքների վրա (կատեգորիայի ուժով ջնջումից հետո)։
- [ ] Համոզվել եմ, որ կապված հաշվետվությունները ճշգրիտ են։

### Որտեղ ստուգել արդյունքը

| Ուժով ջնջվածը | Որտեղ ստուգել |
|---|---|
| **Նյութ** | Պահեստ — չպետք է երևա։ Նյութերի օգտագործման հաշվետվությունում շարժերը պետք է երևան «(ջնջված)» նշումով։ |
| **Ապրանք** | Ապրանքներ — չպետք է երևա։ Հին պատվերներում տողերը մնում են։ |
| **Տարբերակ** | Ապրանքի էջ → Տարբերակատ-ներ — չպետք է երևա։ Հին պատվերներում, արտադրություններում, հաշվետվություններում երևում է «(ջնջված)»։ |
| **Արտադրություն** | Արտադրություն — չպետք է երևա։ Կապված շարժերը մնում են, բայց առանց արտադրության կապի։ |
| **Պատվեր** | Պատվերներ — չպետք է երևա։ Հաշվետվություններում նրա մասը հանվում է։ |
| **Կատեգորիա** | Կատեգորիաներ — չպետք է երևա։ Հին ապրանքները դառնում են «առանց կատեգորիայի»։ |
| **Աուդիտ** | Գործողությունների պատմություն → ֆիլտր ըստ «Ուժով» — տեսնում եք գործողության գրառումը, ով, երբ։ |

## Հավելված. Բացատրությունների բառարան

| Տերմին | Բացատրություն |
|---|---|
| **Արտիկուլ** (`SKU`) | Ապրանքի կամ նյութի եզակի կոդը, որով նա տարբերվում է մյուսներից։ |
| **Տարբերակ** | Մեկ ապրանքի կոնկրետ չափս + գույն համադրությունը։ |
| **Մնացորդ** | Տարբերակի վաճառելի (լավ) միավորների քանակը պահեստում։ |
| **Խոտան** | Արտադրությունից ստացված անորակ միավորների քանակը։ |
| **Առկա քանակ** | Պահեստում տվյալ պահին նյութի փաստացի քանակը։ |
| **Ցածր մնացորդի շեմ** | Քանակ, որից ցածր իջնելու դեպքում նյութը նշվում է որպես «Ցածր մնացորդ»։ |
| **Արխիվացում** | Տվյալի «փափուկ» ջնջում — տվյալը մնում է, բայց անակտիվ է։ |
| **Ուժով ջնջում** | Ադմինի կողմից տվյալի անդարձելի հեռացում, որպեսզի մաքրել կապը այլ տեղ։ Պահպանում է պատմությունը «(ջնջված)» նշումով։ |
| **(ջնջված)** | Հին գրառման մեջ ցույց է տալիս, որ կապված տվյալը հեռացվել է ուժով ջնջման ճանապարհով։ |
| **Շարք** | Պահեստի համար արտադրությունը (առանց կոնկրետ պատվերի)։ |
| **Փուլ** | Արտադրության փուլերը — Կտրում, Մշակում, Որակի վերահսկում, Փաթեթավորում, Պատրաստ է առաքման։ |
| **Աուդիտ** | Համակարգի կողմից ինքնաշխատ պահվող բոլոր գործողությունների պատմությունը։ |
